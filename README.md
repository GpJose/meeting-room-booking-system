# Meeting Room Booking System
 
Консольное Java-приложение для бронирования переговорных комнат в офисе. Pet-проект для практики чистой архитектуры и ООП без использования Spring и других фреймворков — вся логика написана руками, включая работу с данными, валидацию и обработку интервалов времени.
 
## Что умеет
 
- Регистрация и авторизация пользователей (пароли хранятся в виде bcrypt-хэша, не в открытом виде)
- Создание бронирования переговорной комнаты на заданный интервал времени
- Проверка пересечения интервалов — нельзя забронировать уже занятую комнату
- Отмена собственного бронирования (чужие бронирования отменить нельзя)
- Поиск бронирований конкретной комнаты — отдельно текущие и отдельно завершённые/отменённые
- Поиск всех бронирований на заданную дату
- Поиск свободных комнат по минимальной вместимости
- Поиск комнат по набору необходимого оборудования (проектор, экран, видеоконференция и т.д.)
- Валидация пользовательского ввода с понятными сообщениями об ошибках вместо падений или кодов возврата
- 
## Технологии
 
- Java 17
- Maven
- Lombok — сокращение boilerplate (`@Builder`, `@Getter`)
- jBCrypt — хэширование паролей
- JetBrains Annotations
Без базы данных, сети и многопоточности — намеренно: всё хранится в памяти, фокус сделан на дизайне доменной модели и границах ответственности между слоями, а не на инфраструктуре.
 
## Архитектура
 
Слоистая структура, каждый слой работает через интерфейс, а не через конкретную реализацию:
 
```
model/         — доменные сущности и их интерфейсы (Room, User, Booking, Equipment, BookingStatus)
repository/    — хранение данных в памяти (Map / TreeSet), не отдаёт наружу внутреннее состояние напрямую
service/       — бизнес-логика: проверка пересечений интервалов, авторизация, статусы бронирований
factory/       — создание доменных объектов через фабрики, расширяемо под другие реализации Room/User
utils/         — ввод и валидация данных с консоли, хэширование паролей
```
 
Сервисы и контроллер общаются с репозиториями только через интерфейсы — реализация хранения (сейчас `HashMap`/`TreeSet` в памяти) может быть заменена без изменений в остальном коде.
 
 
## Пример работы
 
После запуска доступно консольное меню; часть пунктов требует авторизации:
 
```
0  - Выйти из системы
1  - Авторизоваться
2  - Создать пользователя
3  - Создать встречу
4  - Найти встречи комнаты
5  - Отменить встречу
6  - Найти все завершённые встречи по комнате
7  - Найти комнаты по оборудованиям
8  - Найти комнаты по вместимости
9  - Найти встречи на дату
10 - Закрыть приложение
```
 
Набор переговорных комнат преднастроен при старте — 10 комнат с разной вместимостью и составом оборудования.
 
## Планы
 
- Unit-тесты на ключевую логику: проверка пересечения интервалов, отмена бронирования, поведение репозитория для комнаты без бронирований
- Вынесение вывода в консоль из сервисного слоя в отдельный слой представления
