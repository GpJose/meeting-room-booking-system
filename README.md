# Задача №1: Система бронирования переговорных комнат

**Стек:** Java
**Тип:** монолит, всё in-memory (без БД, без сети, без очередей)

## Контекст

Компании нужен консольный сервис для бронирования переговорок в офисе.

## Базовые требования

- Есть набор комнат (`Room`): название, вместимость, список оборудования (проектор, экран и т.д.).
- Есть бронирования (`Booking`): комната, кто бронирует, дата, время начала и окончания.
- Нельзя создать бронирование, если:
    - комната уже занята в это время (пересечение интервалов);
    - время окончания раньше или равно времени начала.
- Метод поиска: показать список свободных комнат на заданный интервал времени, опционально — с фильтром по минимальной вместимости и/или нужному оборудованию.
- Метод: показать все бронирования конкретной комнаты на конкретный день.
## Дополнительно (по желанию, приветствуется)

- Возможность отменить бронирование.
- Понятные исключения вместо `null`/кодов ошибок при невалидных данных.
- Немного unit-тестов на самую важную логику (проверка пересечения интервалов — то, где обычно прячутся баги).
## Что не важно на этом этапе

UI, база данных, многопоточность — всё в памяти, через `main` или простые тесты можно продемонстрировать сценарии использования.

## Фокус оценки

- Дизайн доменной модели (`Room`, `Booking` и что ещё понадобится)
- Границы ответственности между классами (кто валидирует, кто хранит, кто ищет)
- Чистота интерфейсов и обработка ошибок
  Структура классов и пакетов, способ хранения данных внутри — на усмотрение автора, это часть задачи.
